# 江陈记茶业 · 小红书多账号自动发布系统 实施方案

> 目标：为江陈记茶业搭建一套「素材整理 → 拼图配字 → 文案生成 → 多账号定时发布 → 风控防护」的全自动内容流水线，支持 12~15 个小红书账号每天定时各发 1 条笔记。
>
> 当前状态：需求已明确，素材/服务器/账号为商家已有，本方案为分阶段执行蓝图。素材到手前先完成「阶段1 基础设施」与「阶段2 素材与图片流水线」的开发准备。

---

## 一、总体架构

```
┌─────────────┐   ┌──────────────┐   ┌──────────────┐   ┌──────────────┐
│  素材树状库   │ → │ 图片流水线    │ → │ 文案引擎      │ → │ 发布自动化    │
│  (商家提供)   │   │ 拼图+配字     │   │ 标题+正文+标签 │   │ 多账号队列    │
└─────────────┘   └──────────────┘   └──────────────┘   └──────┬───────┘
        ▲                                                        │
        └──────────────── 风控体系（贯穿全链路） ←───────────────┘
```

| 模块 | 职责 | 由谁提供/开发 |
|------|------|--------------|
| 素材树状库 | 图片按品牌/系列/场景分类存放 | 商家提供素材，我方定规范 |
| 图片流水线 | 选图→拼图→配大字→导出3:4图 | 我方开发 |
| 文案引擎 | 按标题公式+模板批量生成，账号间差异化 | 我方开发 |
| 发布自动化 | 每账号独立环境，定时上传发布 | 我方开发，商家部署运行 |
| 风控体系 | 频率/IP隔离/去重/熔断/告警 | 我方开发（贯穿全部） |

## 二、分阶段执行步骤

### 阶段0：需求与素材确认（商家侧，约3~5天）

**目的**：把"图在哪、发什么、什么风格"定死，否则后面全部返工。

商家需提供：
- [ ] 外包图片素材：全部原图（含 PSD/PNG 分层稿、已出街的成图）
- [ ] 产品线清单：恩施玉露/利川红/茶礼盒/企业定制等，每条的卖点一句话
- [ ] 2~3 篇现有爆款笔记的原始素材包（图+文案），作为风格基准
- [ ] 品牌禁用词：广告法敏感词（最/第一/国家级等）由我方整理，商家确认
- [ ] 每日发布量确认：每账号每天 1 条（已确认）

**交付**：素材清单核对表 + 品牌文案基调（语气、称呼、emoji 用法）。

---

### 阶段1：账号基础设施（商家侧配合，我方出规范，约7~14天）

**红线前提：已注册账号全部处于"在用"状态，必须确认每个账号的当前健康度。**

1. **账号体检**
   - 登录每个账号，检查：是否正常显示、有无"账号异常/被限流"提示、笔记是否可见
   - 记录：账号ID、绑定手机、粉丝数、最近发布内容、有无历史违规
   - 输出《账号健康度台账》：健康/需养号/疑似限流三类

2. **养号基线（强制，新号或低活跃号）**
   - 连续 7~14 天，每账号每天 10~15 分钟真人式浏览
   - 每天点赞3~5条、收藏2~3条、评论1~2条（与茶叶/送礼/武汉相关话题）
   - 养号期**不发笔记**，只积累账号权重

3. **环境隔离（每账号一套，防连坐封号）**
   - 每账号 1 个独立浏览器指纹环境（指纹浏览器：比特/紫鸟/巨象等，商家按环境数购买，约 30~80 元/环境/月）
   - 每账号 1 条独立代理IP（住宅IP最佳，约 20~40 元/账号/月）
   - 同一账号永远只在同一环境+IP 登录操作，禁止混用

4. **登录态管理**
   - 每个环境保存独立 Cookie，标注过期时间（小红书登录态一般 7~30 天）
   - 到期自动提醒重登，不批量重登（重登也要错开时间）

---

### 阶段2：素材与图片流水线（我方开发，素材到手后即可跑）

**树状目录规范（商家素材按此归置）**：

```
江陈记素材库/
├── 01_产品线/
│   ├── 恩施玉露/       # 产品实拍、包装、冲泡图
│   ├── 利川红/
│   ├── 茶礼盒/         # 礼盒各角度、场景图
│   └── 企业定制/
├── 02_场景/
│   ├── 送礼/ 旅游/ 企业团购/ 门店/
├── 03_文字素材/
│   ├── 品牌slogan.txt
│   ├── 卖点库.md        # 每产品的卖点一句话
│   └── 标签库.txt
├── 04_成图输出/          # 流水线产物，按日期归档
└── 05_已用图/            # 发过的图打标记，禁止重复用
```

**图片流水线（对齐江陈记爆款封面风格）**：
- 模板库：四宫格场景图 / 九宫格产品矩阵 / 单图大字（利益点）
- 拼图引擎：选图 → 套模板 → 自动裁切对齐 → 导出 3:4 竖图（1080×1440）
- 配字引擎：按文案标题自动生成大字（可调字体/颜色/描边），文字位置按模板固定
- 去重机制：每张成图存 hash，`已用图`目录记录，防同一张图重复发

**输出**：每账号每日 1 条 = 封面1张 + 正文图3~6张，流水线自动产出当日待发包。

### 阶段3：文案引擎（我方开发）

**标题公式库**（基于江陈记现有爆款提炼）：
| 场景 | 公式 | 示例 |
|------|------|------|
| 送礼 | 场景+结果型 | 送礼就送它❗直接被长辈爆夸❗ |
| 企业 | 结果+数字型 | 宝藏百元茶礼定制促成100万的大订单 |
| 旅游 | 限定+行动型 | 来武汉必带！这款湖北茶叶伴手礼拿得出手 |
| 门店 | 福利+悬念型 | 武汉特产🍵降温红茶特别适合送礼 |

**正文模板**（5段式）：
1. 钩子句（场景代入：过年走亲戚/客户来访/旅游返程）
2. 产品亮点（2~3条，出自卖点库）
3. 场景使用（送礼怎么送/接待怎么摆）
4. 福利/引导（门店位置、定制服务、评论区互动）
5. 标签（固定标签+热门标签组合）

**账号差异化（防重复检测）**：同一天各账号文案自动替换开头词、emoji、句式、标签顺序，相似度控制在 <60%。

---

### 阶段4：发布自动化（我方开发 + 商家部署，部署期约5~7天）

**运行方式**：部署在商家自己的电脑/服务器，常开机，无人值守。

- 发布器：浏览器自动化（每账号独立 profile 环境）
- 定时队列：每天每账号 1 条，发布时间段在 9:00~22:00 之间错开（相邻账号间隔 ≥30 分钟）
- 发布流程：登录态校验 → 读当日待发包 → 上传图片 → 填标题/正文/标签 → 发布 → 记录结果（成功/失败/被拦截）
- 结果日志：每账号一条记录（发布时间、状态、异常原因），生成日报

**试点要求**：先 1 个账号试跑 3 天（功能验证），再每周 +3 账号扩容，直至全量。

---

### 阶段5：风控体系（贯穿全部，我方开发）

**硬规则（不可突破）**：
- [ ] 每账号每日 ≤1 条；相邻账号发布间隔 ≥30 分钟
- [ ] 新号/低活跃号养 7~14 天才开发
- [ ] 每账号独立环境+独立IP，永不混用
- [ ] 发布前图片 hash + 文案相似度双重去重，重复即拦截
- [ ] 发布后 30~120 分钟内不做任何互动（随机延时）

**异常熔断**：
- 触发验证码/滑块 → 停该账号 2~3 小时，人工复核后再继续
- 登录失败、发布失败率 >20% → 停该账号并告警
- 收到"内容违规"提示 → 立即停该账号，记录违规内容编号

**告警机制**：日报自动汇总异常，异常账号在日报首行标红。

---

### 阶段6：验收与迭代（共同，持续）

**验收标准**：
- 单账号试跑 3 天：发布成功率 100%，无风控拦截
- 全量 15 账号：每日 15 条全部按时发布，7 天无账号异常
- 数据指标：单条笔记曝光≥500、赞藏≥30（茶业垂类基准）或由商家设定

**迭代**：
- 每周复盘：曝光/赞藏/涨粉数据 → 淘汰差封面模板、优化标题公式
- 素材消耗跟踪：已用图目录防重复，素材见底前 1 周提醒商家补图

## 三、成本与风险（必须提前告诉商家）

| 项目 | 月成本（估） |
|------|------|
| 指纹浏览器环境 ×15 | 约 450~1200 元 |
| 住宅代理IP ×15 | 约 300~600 元 |
| 服务器（如无现成） | 约 100~200 元 |
| **合计** | **约 850~2000 元/月** |

**风险（实话实说）**：
1. **封号风险**：批量多账号营销是平台红线，即使按上述风控执行仍非零风险；账号丢失无法找回，需商家接受
2. **内容合规**：广告法禁用词（最/第一/顶级等）必须过滤，茶类"养生/治病"功效话术禁止
3. **登录态维护**：小红书登录态会过期，需要定期人工扫码/验证码重登（重登无法全自动化）
4. **素材依赖**：图片是外包素材，若商家停止供图，流水线即停

## 四、下一步行动（我现在能做的）

1. 本方案评审：商家确认发布量、成本预算、风险接受
2. 我方先行开发（不依赖素材的部分）：

   - 发布器框架 + 日志/日报
   - 风控规则引擎（去重、熔断、间隔调度）
3. 商家侧并行：账号体检台账、素材按树状目录归置、购买指纹环境/代理IP
